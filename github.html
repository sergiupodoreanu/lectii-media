GitHub – contul, depozitul de teme și site-ul cu GitHub Pages

Clasa a XII-a · Producție media · Modulul „Montajul și verificarea documentelor digitale”

Cuprins Fișa de laborator Lecția anterioară: Markdown avansat

1. Tema lecției

Lecția prezintă GitHub, un serviciu online gratuit în care se păstrează fișiere și versiunile lor. Fiecare elev își face un cont, un depozit pentru teme și proiecte și un site de portofoliu, publicat cu GitHub Pages. Tema se predă printr-o adresă (link), nu prin fișiere trimise pe email sau pe stick.

La sfârșitul lecției se cunosc:

  • ce este GitHub și ce înseamnă depozit, commit și versiune;
  • crearea contului și păstrarea lui în siguranță;
  • crearea depozitului și organizarea lui pe foldere, câte unul pentru fiecare temă;
  • încărcarea, înlocuirea și ștergerea fișierelor din browser;
  • publicarea depozitului ca site, cu GitHub Pages, și scrierea paginii index.html;
  • predarea temei prin link și regulile de publicare.

Tot ce se face în lecție se face din browser, fără programe instalate. Interfața GitHub este în limba engleză; numele butoanelor sunt date exact cum apar pe ecran, cu traducerea alături.

2. Ce este GitHub

GitHub – serviciu online (github.com) în care se păstrează fișiere, împreună cu toate versiunile lor. Este folosit în toată lumea de programatori, dar și pentru documentație, pagini web și portofolii.
Depozit (în engleză repository, prescurtat repo) – un „dosar” pe GitHub, cu foldere și fișiere, care are o adresă proprie. Un cont poate avea oricâte depozite.
Commit – o salvare cu mesaj: fișierele adăugate sau modificate se înregistrează în depozit împreună cu o scurtă descriere, data, ora și autorul.
Versiune – starea unui fișier la un anumit commit. Versiunile vechi nu se pierd: se pot vedea oricând în istoric.

3. Contul

Contul se face o singură dată și este personal: GitHub permite un singur cont gratuit de persoană, de la vârsta de 13 ani. Este nevoie de o adresă de email la care există acces în momentul înscrierii (pe telefon sau pe calculator).

  1. În browser se deschide adresa github.com/signup (sau github.com, apoi butonul Sign up).
  2. Se completează câmpurile din tabelul de mai jos.
  3. Se apasă Create account.
  4. GitHub cere confirmarea adresei de email: se deschide emailul primit și se introduce codul din mesaj. Dacă apare și o verificare de tip puzzle, se rezolvă.
  5. Numele de utilizator și parola se notează într-un loc sigur.

Nume de utilizator (username) – numele unic al contului. Apare în toate adresele: github.com/ion-popescu și ion-popescu.github.io.

Alegerea numelui de utilizator

Numele apare în adresa portofoliului, care ajunge la profesori și, mai târziu, la angajatori. Se alege un nume serios și ușor de dictat, scris cu litere mici: ion-popescu, ionpopescu-media. Nu se aleg porecle sau șiruri de cifre: xXshadow2008Xx.

Siguranța contului

  • Parola nu se spune nimănui și nu se folosește aceeași parolă ca la alte conturi.
  • Pe calculatorul din laborator, parola nu se salvează în browser, iar la sfârșitul orei se iese din cont: clic pe imaginea de profil (dreapta sus), apoi Sign out.
  • GitHub recomandă autentificarea în doi pași (în engleză two-factor authentication, 2FA): pe lângă parolă se cere un cod generat pe telefon. Se activează din setările contului.
  • La github.com/settings/emails există opțiunea Keep my email addresses private; cu ea bifată, adresa de email nu apare în istoricul public al depozitului.

4. Depozitul

Pentru toate temele și proiectele unui an școlar ajunge un singur depozit, organizat pe foldere.

  1. Se deschide adresa github.com/new (sau semnul + din dreapta sus, apoi New repository).
  2. La Repository name se scrie numele depozitului: portofoliu-media.
  3. La Description (opțional) se scrie o descriere scurtă: „Teme și proiecte – clasa a XII-a, Producție media”.
  4. La vizibilitate se alege Public.
  5. Se activează opțiunea Add README (poziția On).
  6. Se apasă Create repository.

Depozitul are acum adresa github.com/ion-popescu/portofoliu-media și conține un singur fișier, README.md.

5. Organizarea portofoliului

Fiecare temă are folderul ei. În rădăcina depozitului (nivelul de sus) rămân numai README.md și index.html.

│   └── afis.png
├── tema-02-pliant/

    └── imagini/

Rădăcina depozitului – nivelul de sus al depozitului, cel care se vede la deschiderea adresei lui.

Ce se încarcă:

  • fișierul final, în format de predare: PDF pentru documente, PNG sau JPG pentru imagini;
  • o imagine de prezentare (PNG sau JPG, cu lățimea de cel mult 1600 px), care se afișează direct în pagină;
  • fișierul-sursă (.sla din Scribus, .svg din Inkscape, .md), dacă este cerut și are mărime rezonabilă.

Limite: din browser, un fișier poate avea cel mult 25 MB și se pot încărca cel mult 100 de fișiere o dată. Filmele și fișierele-sursă foarte mari nu se încarcă în depozit; se păstrează în OneDrive, iar în depozit se pune numai linkul către ele.

6. Încărcarea fișierelor

  1. Se deschide depozitul: github.com/ion-popescu/portofoliu-media.
  2. Deasupra listei de fișiere se apasă Add file, apoi Upload files.
  3. Din File Explorer se trage folderul temei (de exemplu tema-01-afis) în pagina de încărcare. Tras ca folder, ajunge în depozit tot ca folder, cu fișierele în el. (Fișiere separate se pot alege și cu choose your files.)
  4. Se așteaptă până când toate fișierele apar în lista de sub zona de încărcare.
  5. Jos, la Commit changes, se scrie mesajul: „Tema 1 – afiș”.
  6. Se apasă butonul verde Commit changes.

Folderul gol nu există

În depozit, un folder există numai dacă are cel puțin un fișier în el. Un folder nou se obține fie prin tragerea unui folder cu fișiere, fie cu Add file → Create new file, scriind în câmpul de nume calea completă, cu bară oblică: tema-02-pliant/note.md.

Mesajul de commit

Mesajul spune, pe scurt, ce s-a schimbat. Rămâne în istoric și îl citesc atât profesorul, cât și autorul, peste câteva luni.

7. Corectarea, ștergerea și istoricul

OperațieCum se face
Înlocuirea unui fișier corectatse intră în folderul temei și se încarcă din nou fișierul, cu exact același nume (Add file → Upload files). Fișierul vechi este înlocuit, iar versiunea veche rămâne în istoric.
Modificarea unui fișier-text (.md, .html)se deschide fișierul, se apasă butonul cu creion (dreapta sus), se modifică textul, apoi Commit changes…
Ștergerea unui fișierse deschide fișierul, se apasă butonul cu trei puncte (dreapta sus), apoi Delete file și Commit changes…
Istoricul depozituluipe prima pagină a depozitului, linkul cu ceas și numărul de commituri (Commits). Adresa directă: github.com/ion-popescu/portofoliu-media/commits
Istoricul unui fișierse deschide fișierul și se apasă History

Regulă: nu se încarcă variante cu nume diferite (afis-v2.pdf, afis-final.pdf). Se păstrează un singur nume, iar variantele le ține istoricul.

Atenție: un fișier șters dispare din lista de fișiere, dar rămâne în istoric. Ce a fost încărcat o dată într-un depozit public trebuie considerat public.

8. Fișierul README.md

README.md – fișierul de prezentare al depozitului. GitHub îl afișează formatat, sub lista de fișiere. Se scrie în Markdown, cu sintaxa din lecțiile Markdown de bază și Markdown avansat.

Se modifică direct în browser: clic pe README.md, butonul cu creion, apoi Commit changes…. Înainte de salvare, fila Preview arată cum va fi afișat.

9. Publicarea site-ului cu GitHub Pages

GitHub Pages – funcția GitHub care transformă fișierele unui depozit într-un site, la o adresă de forma utilizator.github.io/depozit.
Site static – site format numai din fișiere gata făcute (HTML, imagini, PDF), afișate așa cum sunt. Un portofoliu este un site static.

Pages se activează o singură dată pentru un depozit:

  1. Se deschide depozitul și se apasă fila Settings.
  2. În meniul din stânga se apasă Pages. Adresa directă: github.com/ion-popescu/portofoliu-media/settings/pages.
  3. La Build and deployment, în lista Source, se alege Deploy from a branch.
  4. La Branch se alege main, iar la folder / (root).
  5. Se apasă Save.
  6. Se așteaptă câteva minute și se reîncarcă pagina. Sus apare adresa site-ului și butonul Visit site.
Ramură (în engleză branch) – o linie de lucru a depozitului. Un depozit nou are o singură ramură, numită main; în ea se află toate fișierele din lecție.
/ (root) – rădăcina depozitului: site-ul se face din tot depozitul, nu dintr-un singur folder.

De reținut:

  • prima pagină a site-ului este fișierul index.html din rădăcina depozitului; dacă nu există, este afișat README.md;
  • după fiecare commit, site-ul se actualizează singur; modificarea poate apărea după cel mult 10 minute;
  • dacă pagina arată tot varianta veche, se reîncarcă forțat: Ctrl+F5;
  • site-ul este public: îl vede oricine are adresa.

Reguli:

  • căile sunt relative la rădăcina depozitului: tema-01-afis/afis.pdf, fără C:\… și fără github.com/…;
  • calea se scrie exact ca numele folderului și al fișierului, cu aceleași litere mari și mici: afis.png și Afis.PNG sunt fișiere diferite;
  • în pagină se afișează imagini (PNG, JPG, SVG); un PDF nu se afișează cu <img>, ci se deschide printr-o legătură;
  • la fiecare temă nouă se adaugă în index.html un bloc nou (titlu, descriere, imagine, legătură), înainte de </body>;
  • după commit, fiecare legătură se încearcă pe site, nu numai în depozit.

11. Predarea unei teme

  1. Fișierele temei se încarcă în folderul ei, cu un mesaj de commit potrivit.
  2. În index.html se adaugă blocul temei.
  3. Se deschide site-ul și se verifică imaginea și legătura.
  4. Din bara de adrese a browserului se copiază adresa folderului din depozit, de exemplu https://github.com/ion-popescu/portofoliu-media/tree/main/tema-01-afis.
  5. Adresa se trimite profesorului, pe platforma clasei, la tema respectivă.

Data predării este data ultimului commit din folderul temei. O modificare făcută după termen se vede în istoric.

12. Reguli de publicare

  • Date personale: nu se publică CNP, adresă, număr de telefon, acte, note, fotografii ale altor persoane fără acordul lor. În portofoliu apar numele autorului, clasa și lucrările.
  • Parole: niciun fișier încărcat nu conține parole sau coduri de acces.
  • Drepturi de autor: se publică numai lucrări proprii. Fotografiile, fonturile și ilustrațiile preluate se folosesc numai cu licență care permite publicarea, iar sursa se menționează.
  • Lucrarea altcuiva nu se copiază în depozitul propriu; istoricul arată cine și când a încărcat fiecare fișier.
  • Conținut: portofoliul este o carte de vizită profesională; se publică numai ce poate fi arătat unui angajator.
  • Ce s-a publicat rămâne în istoric, chiar dacă fișierul este șters. Se verifică înainte de commit, nu după.
