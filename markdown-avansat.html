Markdown avansat – de la notițe la document publicat

Clasa a XII-a · Producție media · Modulul „Montajul și verificarea documentelor digitale”

Cuprins Lecția anterioară: Markdown de bază Fișa de laborator Fișierul-exemplu (.md)

1. Tema lecției

În lecția anterioară, Markdown a fost folosit pentru texte cu structură simplă. În această lecție, același limbaj este folosit pentru un document de lucru complet: documentul de proiect al unui afiș, cu tabele, etape de lucru, note de subsol, formule și diagrame, convertit apoi în Word și HTML și publicat.

La sfârșitul lecției se cunosc:

  • elementele avansate de sintaxă: tabele cu aliniere, liste de sarcini, note de subsol, blocuri de cod, antet de metadate, formule, diagrame;
  • programele în care aceste elemente se afișează corect;
  • conversia unui fișier .md în Word și HTML cu programul Pandoc;
  • rolul fișierului README.md și verificarea unui document Markdown înainte de predare.

Recapitulare – sintaxa de bază

Markdown este un limbaj de marcare ușoară: formatarea se scrie cu semne simple, direct în text. Fișierul are extensia .md, este text simplu și se deschide cu orice editor de text.
ElementSe scrieSe vede

Text îngroșat**important**important
Text cursiv*termen*termen
Listă cu buline- element• element
Listă numerotată1. pas1. pas
Legătură[text](https://adresa.ro)text
Imagine![descriere](imagini/foto.png)imaginea din fișierul indicat

Regulă generală: după semnele #, -, 1. și > urmează un spațiu; între paragrafe, liste, tabele și titluri se lasă un rând gol.

2. Dialectele Markdown

Markdown a apărut în 2004 cu un set mic de reguli. Ulterior, fiecare program a adăugat elemente proprii. Aceste variante se numesc dialecte.

CommonMark este specificația (descrierea oficială, precisă) a sintaxei de bază, respectată de aproape toate programele.
GFM (GitHub Flavored Markdown) este dialectul folosit de platforma GitHub: CommonMark plus tabele, liste de sarcini, text tăiat și legături automate. Este dialectul cel mai răspândit; elementele din această lecție aparțin în mare parte dialectului GFM.

Consecință practică: un element avansat poate fi afișat corect într-un program și ca text brut în altul. De aceea documentul se verifică în programul în care va fi citit (vezi tabelul din capitolul 9).

3. Tabele cu aliniere

Un tabel se scrie cu bare verticale | între coloane. Al doilea rând, format din liniuțe, separă capul de tabel de date. Poziția semnului : în acest rând stabilește alinierea coloanei.

Se scrie
| Element    | Tipar        | Ecran    |
|:-----------|:------------:|---------:|
| Rezoluție  | 300 dpi      | 96 dpi   |
| Culoare    | CMYK         | RGB      |
| Format     | PDF/X-4      | PNG      |
Se vede
ElementTiparEcran
Rezoluție300 dpi96 dpi
CuloareCMYKRGB
FormatPDF/X-4PNG
În rândul de separareAlinierea coloaneiSe folosește pentru
:---la stângatext
:---:centratvalori scurte, simboluri
---:la dreaptanumere, prețuri

Reguli:

  • toate rândurile au același număr de bare |;
  • înaintea tabelului se lasă un rând gol;
  • barele nu trebuie să fie aliniate una sub alta – alinierea în fișierul sursă ajută doar la citire;
  • o celulă conține un singur rând de text; pentru tabele complicate (celule unite, mai multe paragrafe în celulă) Markdown nu este potrivit.

4. Liste de sarcini, text tăiat, note de subsol

Liste de sarcini

O listă de sarcini este o listă în care fiecare element are o casetă de bifat. Arată ce etape ale unei lucrări sunt terminate și ce a rămas de făcut.
Se scrie
- [x] Notarea cerințelor clientului
- [x] Scrierea textului
- [ ] Machetarea în Scribus
- [ ] Exportul PDF
Se vede
  • ☑ Notarea cerințelor clientului
  • ☑ Scrierea textului
  • ☐ Machetarea în Scribus
  • ☐ Exportul PDF

Între paranteze se află un spațiu (sarcină nefăcută) sau litera x (sarcină terminată). -[] și - [] sunt greșite.

Text tăiat

Textul încadrat de câte două tilde, ~~Ziua Ușilor Deschise~~, apare tăiat cu o linie: Ziua Ușilor Deschise. Se folosește pentru a arăta o variantă la care s-a renunțat, fără a o șterge.

Note de subsol

O notă de subsol este o explicație scurtă, așezată la sfârșitul paginii sau al documentului și legată de text printr-un număr.
Se scrie
Fișierul trece prin preflight[^pf]
înainte de tipar.

[^pf]: Preflight – verificarea tehnică
a fișierului înainte de tipar.
Se vede

Fișierul trece prin preflight1 înainte de tipar.

1 Preflight – verificarea tehnică a fișierului înainte de tipar.

În text se pune trimiterea [^nume], iar oriunde în fișier (de obicei la sfârșit) se scrie definiția [^nume]: textul notei. Numele este la alegere (pf, 1, sursa); numerotarea se face automat, în ordinea apariției în text.

5. Blocuri de cod

Un bloc de cod este un fragment afișat exact așa cum a fost scris, cu font de lățime fixă, fără a fi interpretat ca Markdown. Se încadrează între două rânduri formate din trei accente grave ```. După primele trei accente se poate scrie numele limbajului; programul colorează atunci cuvintele-cheie (evidențierea sintaxei).

Se scrie
```html
<h1>Ziua Porților Deschise</h1>
<p class="data">24 octombrie</p>
```
Se vede
<h1>Ziua Porților Deschise</h1>
<p class="data">24 octombrie</p>

Blocurile de cod se folosesc pentru: cod HTML/CSS, comenzi, scripturi Scribus (Python), conținutul unui alt fișier. Accentul grav se află pe tasta de sub Esc.

6. Antetul de metadate

Metadatele sunt date despre document: titlu, autor, dată, limbă. Antetul de metadate (în engleză front matter) este un bloc așezat chiar la începutul fișierului, între două rânduri formate din trei liniuțe ---. Este scris în formatul YAML: câte o pereche nume: valoare pe fiecare rând.
Se scrie (primele rânduri din fișier)
---
title: "Afiș Ziua Porților Deschise"
author: "Popescu Ana, clasa a XII-a Media"
date: "2026-10-05"
lang: ro
---
Se folosește la
  • conversie: Pandoc pune titlul, autorul și data la începutul documentului Word/HTML și în proprietățile fișierului;
  • limbă: lang: ro stabilește limba documentului (despărțire în silabe, ghilimele, cititoare de ecran);
  • organizare: Obsidian afișează antetul ca „Proprietăți” și permite căutarea după ele.

Reguli: antetul începe din primul rând al fișierului; după două puncte urmează un spațiu; valorile care conțin semne speciale (:, #, ghilimele) se scriu între ghilimele drepte "…"; numele câmpurilor recunoscute de Pandoc sunt în engleză (title, author, date, lang).

7. Formule

Formulele se scriu în notația LaTeX (un limbaj de scriere a textelor științifice), între semne dolar: $…$ pentru o formulă în rând și $$…$$ pentru o formulă pe rând separat, centrată.

Se scrie
$$N = \frac{L \cdot R}{25,4}$$
Se vede
N = L · R25,4

Legenda notațiilor:

  • N – numărul de pixeli necesar pe o latură a imaginii (px);
  • L – lungimea laturii tipărite, în milimetri (mm);
  • R – rezoluția de tipar, în puncte pe inch (dpi);
  • 25,4 – numărul de milimetri dintr-un inch.

Exemplu numeric

Afiș A3 (297 × 420 mm) tipărit la 300 dpi:
lățime: N = 297 · 300 / 25,4 ≈ 3508 px; înălțime: N = 420 · 300 / 25,4 ≈ 4961 px.
Imaginea de fundal trebuie să aibă cel puțin 3508 × 4961 px.

8. Diagrame

Mermaid este un limbaj în care o diagramă se descrie în text, iar programul o desenează. Diagrama se scrie într-un bloc de cod cu numele mermaid. Avantaj: diagrama se modifică la fel de ușor ca textul și rămâne în același fișier cu documentul.

Tipul cel mai folosit este schema logică (în engleză flowchart): casete legate prin săgeți, care arată etapele unui proces.

```mermaid
flowchart LR
    A[Cerințele clientului] --> B[Text în Markdown]
    B --> C[Machetare în Scribus]
    C --> D{Verificare}
    D -- erori --> C
    D -- corect --> E[Export PDF]
```
Se vede
Se scrieSemnificație
flowchart LRschemă logică desenată de la stânga la dreapta (Left–Right); TD = de sus în jos (Top–Down)
A[Text]casetă dreptunghiulară cu numele intern A și textul afișat „Text” – o etapă
D{Text}romb – o decizie (întrebare cu mai multe răspunsuri)
A --> Bsăgeată de la A la B
D -- erori --> Csăgeată cu text pe ea

Diagrama se poate încerca, fără instalare, în editorul online mermaid.live: în stânga se scrie textul, în dreapta apare desenul, care se poate salva ca imagine PNG sau SVG.

9. Imagini, legături și structura folderului

Un document Markdown nu conține imaginile, ci doar trimiteri către fișierele-imagine. De aceea documentul și imaginile se păstrează împreună, într-un folder de proiect.

Structura folderului

Textul dintre paranteze drepte este textul alternativ: descrierea imaginii, citită de cititoarele de ecran și afișată când imaginea lipsește.

Cale relativă – drumul către un fișier, pornind de la folderul în care se află documentul: imagini/schita.png.
Cale absolută – drumul complet, de la rădăcina discului: C:\Users\Ana\Desktop\schita.png.

Reguli:

  • se folosesc numai căi relative – o cale absolută funcționează doar pe calculatorul pe care a fost scrisă;
  • în cale se scrie bara oblică /, nu \;
  • numele de fișiere și foldere: litere mici, fără spații și fără diacritice, cuvintele legate cu liniuță (schita-afis.png, nu Schiță Afiș.png);
  • majusculele contează la publicarea pe internet: Schita.png și schita.png sunt fișiere diferite.

10. Conversia cu Pandoc

Pandoc este un program gratuit care convertește documente dintr-un format în altul: din Markdown în Word (.docx), HTML, EPUB (carte electronică) și altele. Nu are fereastră proprie: se folosește din linia de comandă – fereastra în care comenzile se scriu ca text.

Pregătire

  1. Pandoc se instalează de pe pandoc.org (fișierul .msi pentru Windows).
  2. Folderul proiectului se deschide în VS Code (File → Open Folder), apoi se deschide terminalul: Terminal → New Terminal. Terminalul pornește direct în folderul proiectului; comenzile se dau din acest folder, altfel Pandoc nu găsește imaginile.
  3. Instalarea se verifică cu comanda pandoc --version; se afișează numărul versiunii.

Comenzi

RezultatComandă
Document Wordpandoc README.md -o proiect.docx
Pagină HTML completăpandoc README.md -s --mathml -o proiect.html
Word cu cuprinspandoc README.md --toc -o proiect.docx
Word cu stilurile dintr-un șablonpandoc README.md --reference-doc=sablon.docx -o proiect.docx
Carte electronicăpandoc README.md --mathml -o proiect.epub

Legenda comenzii:

  • pandoc – numele programului;
  • README.md – fișierul de intrare (sursa);
  • -o – de la output (ieșire): urmează numele fișierului rezultat; formatul se deduce din extensie;
  • -s – de la standalone (de sine stătător): pagina HTML rezultată este completă, cu titlu și codare a caracterelor;
  • --mathml – formulele sunt scrise în HTML în formatul MathML, afișat direct de browser;
  • --toc – de la table of contents: se adaugă cuprinsul, construit din titluri;
  • --reference-doc=sablon.docx – documentul rezultat preia fonturile și stilurile (Heading 1, Body Text…) din fișierul Word indicat.

Fișierul PDF

Pentru conversia directă în PDF, Pandoc are nevoie de un program suplimentar. Calea simplă: fișierul .docx se deschide în Word și se salvează cu File → Save As → PDF, sau fișierul .html se deschide în browser și se tipărește cu Ctrl+P → Save as PDF.

Diagrama la conversie

Pandoc nu desenează diagramele Mermaid: în Word apare textul diagramei. Soluție: diagrama se salvează ca imagine PNG din mermaid.live, se pune în folderul imagini/ și se inserează în document ca imagine.

11. Fișierul README.md și publicarea

README.md („citește-mă”) este fișierul de prezentare al unui proiect: se află în folderul principal și explică ce conține proiectul. GitHub este o platformă online pe care se păstrează și se publică proiecte formate din fișiere; folderul unui proiect pe GitHub se numește depozit (în engleză repository).

GitHub afișează automat conținutul fișierului README.md, formatat, pe pagina depozitului. Pentru un portofoliu, README.md este pagina de prezentare.

Structura obișnuită a unui README:

  1. Titlul proiectului și o descriere de 1–2 rânduri;
  2. Conținutul – ce fișiere și foldere există și ce cuprind (tabel sau listă);
  3. Starea lucrării – listă de sarcini;
  4. Imagini – schițe, capturi, rezultatul final;
  5. Autor, dată, programe folosite.

Pe GitHub se afișează direct tabelele, listele de sarcini, notele de subsol, formulele și diagramele Mermaid. Fișierele se încarcă din browser, cu Add file → Upload files, păstrând structura de foldere.

12. Inteligența artificială și Markdown

Asistenții AI (Gemini, Claude, ChatGPT) scriu răspunsurile în Markdown; de aceea pot fi folosiți direct în lucrul cu fișiere .md:

  • tabel din date brute: „Transformă lista următoare într-un tabel Markdown cu coloanele Element, Tipar, Ecran”;
  • diagramă din descriere: „Scrie o schemă logică Mermaid pentru etapele: cerințe, text, machetare, verificare, export; la verificare, în caz de erori, se revine la machetare”;
  • verificare: „Verifică fișierul Markdown de mai jos: ierarhia titlurilor, tabele, note de subsol fără definiție, legături greșite”.

Rezultatul se verifică întotdeauna în previzualizare: tabelul are toate coloanele, diagrama se desenează, datele nu au fost schimbate. Răspunderea pentru document aparține autorului, nu asistentului.

13. Limitele limbajului Markdown

Markdown descrie structura documentului (titluri, liste, tabele), nu aspectul lui. Nu se pot stabili: fonturi, culori, coloane de text, poziția exactă a unei imagini, dimensiunea paginii.

LucrareInstrument potrivit
Notițe, document de proiect, README, text pentru pagină webMarkdown
Referat, raport cu aspect standardMarkdown + Pandoc → Word
Afiș, pliant, revistă – aspect controlat la milimetruScribus (program DTP)
Siglă, ilustrație vectorialăInkscape

Fluxul obișnuit în producția media: textul se scrie și se verifică în Markdown, apoi se importă în programul de machetare, unde primește aspectul final.

14. Verificarea documentului înainte de predare

  1. Titluri: un singur titlu de nivel 1; nivelurile nu se sar (după ## urmează ###, nu ####).
  2. Tabele: același număr de coloane pe toate rândurile; alinierea numerelor la dreapta.
  3. Liste de sarcini: starea bifelor corespunde realității.
  4. Note de subsol: fiecare trimitere [^nume] are o definiție și invers.
  5. Imagini: toate se afișează; căi relative; text alternativ completat.
  6. Legături: fiecare legătură se deschide.
  7. Antet de metadate: titlu, autor, dată, limbă – completate corect.
  8. Diacritice: fișier salvat în codarea UTF-8; literele ă, â, î, ș, ț apar corect și după conversie.
  9. Conversie: fișierele .docx și .html se deschid și se compară cu previzualizarea.
