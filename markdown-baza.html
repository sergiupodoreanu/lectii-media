Cuprins Fișa de laborator Fișierul-exemplu (.md) Lecția următoare: Markdown avansat

1. Tema lecției

Lecția prezintă sintaxa de bază a limbajului Markdown, element cu element: cum se scrie, cum se vede și ce greșeli apar. Cu aceste elemente se poate scrie orice text structurat: un articol, un ghid, o pagină de prezentare.

La sfârșitul lecției se cunosc:

  • diferența dintre text simplu și text formatat și rolul unui limbaj de marcare;
  • crearea unui fișier .md și previzualizarea lui;
  • elementele de bază: paragrafe, titluri, evidențieri, liste, legături, imagini, citate, cod, linie orizontală;
  • scrierea caracterelor speciale și corectarea greșelilor frecvente.

Tabelele, listele de sarcini, notele de subsol, formulele, diagramele și conversia în Word sunt tratate în lecția Markdown avansat.

2. Ce este Markdown

Text simplu – text format numai din caractere (litere, cifre, semne), fără fonturi, culori sau mărimi. Exemplu: un fișier .txt.
Text formatat – text care are și aspect: titluri, îngroșări, liste, imagini. Exemplu: un document Word.
Limbaj de marcare – un sistem de semne introduse în text pentru a-i descrie structura (ce este titlu, ce este listă, ce este important). HTML și Markdown sunt limbaje de marcare.

Markdown este un limbaj de marcare ușoară: structura se scrie cu semne simple (#, *, -, >), direct în text. Fișierul rămâne text simplu, cu extensia .md, iar un program îl afișează formatat. Limbajul a fost creat în 2004 de John Gruber, cu scopul ca textul să poată fi citit ușor și în forma nemarcată.

Randare – transformarea textului marcat în text formatat, afișat pe ecran.
Previzualizare – fereastra în care se vede randarea, în timp ce se scrie.

Cu ce se deschidecu orice editor de text, pe orice sistemcu Word sau un program compatibil
Mărimea fișieruluicâțiva kilobytesde zeci de ori mai mare

Ideea de bază: conținutul este separat de aspect. Autorul scrie textul și structura lui; aspectul se adaugă ulterior. Același fișier .md poate deveni pagină web, document Word, carte electronică sau text importat în Scribus.

Unde se folosește: pagini de prezentare pe GitHub, notițe (Obsidian), documentație, mesaje în Teams și Discord, articole pentru pagini web. Asistenții AI (Gemini, Claude, ChatGPT) scriu răspunsurile în Markdown – de aici apar semnele ** și # atunci când un răspuns este copiat ca text simplu.

Primul fișier în VS Code

  1. Se creează un folder de lucru și se deschide în VS Code: File → Open Folder.
  2. Se creează fișierul: File → New File, cu numele primul-fisier.md. Extensia .md se scrie obligatoriu.
  3. Se deschide previzualizarea alături de text: Ctrl+K, apoi V. (Ctrl+Shift+V deschide previzualizarea într-o filă separată.)
  4. Se scrie textul în stânga; randarea apare în dreapta. Fișierul se salvează cu Ctrl+S.

Extensia fișierului

Windows ascunde implicit extensiile, iar un fișier poate ajunge să se numească articol.md.txt. Extensiile se afișează din File Explorer: View → Show → File name extensions.

4. Paragrafe și rânduri

Un paragraf este un grup de rânduri de text, fără rânduri goale între ele. Două paragrafe se despart printr-un rând gol.
Se scrie
Primul paragraf este scris
pe două rânduri în fișier.

Al doilea paragraf începe
după un rând gol.
Se vede

Primul paragraf este scris pe două rânduri în fișier.

Al doilea paragraf începe după un rând gol.

Atenție: o singură apăsare a tastei Enter nu produce rând nou la afișare – rândurile alăturate sunt unite în același paragraf. Mai multe rânduri goale la rând sunt afișate ca unul singur.

Rând nou în același paragraf

Uneori este nevoie de rând nou fără paragraf nou: o adresă, o semnătură, versuri. Rândul nou se obține cu o bară oblică inversă \ la sfârșitul rândului sau cu două spații la sfârșitul rândului.

Se scrie
Redacția revistei\
Clasa a XII-a Media\
Buzău
Se vede

Redacția revistei
Clasa a XII-a Media
Buzău

Cele două spații de la sfârșitul rândului nu se văd în fișier și se pierd ușor; bara \ este varianta vizibilă.

5. Titluri

Un titlu se scrie cu semnul # la începutul rândului, urmat de un spațiu. Numărul de semne # dă nivelul titlului, de la 1 (cel mai important) la 6.

Se scrie
# Titlul documentului
## Capitol
### Subcapitol
#### Secțiune
Se vede
Titlul documentului
Capitol
Subcapitol
Secțiune
Ierarhia titlurilor – ordinea nivelurilor într-un document: titlul de nivel 1 este titlul documentului, titlurile de nivel 2 sunt capitolele, cele de nivel 3 sunt subcapitolele capitolului în care se află.

Reguli:

  • un document are un singur titlu de nivel 1;
  • nivelurile nu se sar: după ## urmează ###, nu ####;
  • nivelul se alege după structură, nu după mărimea dorită a literelor;
  • înainte și după titlu se lasă un rând gol;
  • titlul nu se termină cu punct și nu se scrie îngroșat.

Din titluri, programele construiesc automat cuprinsul. În VS Code, structura titlurilor se vede în panoul Outline (în stânga, sub lista de fișiere) – cel mai rapid mod de a verifica ierarhia.

  • fiecare evidențiere se închide cu aceleași semne cu care a fost deschisă;
  • în locul asteriscului se poate folosi liniuța de subliniere (_cursiv_, __îngroșat__); într-un document se folosește un singur fel;

  • Markdown de bază nu are subliniere – pe ecran, textul subliniat se confundă cu o legătură.

7. Liste

Listă cu buline

Fiecare element începe cu o liniuță - urmată de un spațiu. Se folosește când ordinea nu contează.

Listă numerotată

Fiecare element începe cu un număr, punct și spațiu: 1. . Se folosește când ordinea contează: pași de lucru, clasamente.

Se scrie
Reguli:

- cel mult două fonturi;
- contrast puternic;
- text scurt.

Pași:

1. Se citesc cerințele.
2. Se aleg fonturile.
3. Se face proba de tipar.
Se vede

Reguli:

  • cel mult două fonturi;
  • contrast puternic;
  • text scurt.

Pași:

  1. Se citesc cerințele.
  2. Se aleg fonturile.
  3. Se face proba de tipar.

Listă în listă

O listă se poate afla în interiorul unui element al altei liste. Elementele listei interioare se scriu retrase cu patru spații (tasta Tab în VS Code).

Se scrie
1. Se citesc cerințele.
2. Se aleg fonturile:
    - un font pentru titlu;
    - un font pentru text.
3. Se verifică licența.
Se vede
  1. Se citesc cerințele.
  2. Se aleg fonturile:
    • un font pentru titlu;
    • un font pentru text.
  3. Se verifică licența.

Reguli:

  • înaintea listei se lasă un rând gol; fără el, unele programe lipesc lista de paragraful de deasupra;
  • după liniuță sau după număr urmează un spațiu;
  • într-o listă se folosește același semn pentru toate bulinele (-; sunt acceptate și * și +);
  • numerotarea se face automat: lista începe de la primul număr scris și continuă din unu în unu, chiar dacă numerele următoare sunt greșite; la adăugarea unui pas la mijloc, numerele nu trebuie rescrise.

8. Legături

O legătură (link) este un text pe care se face clic pentru a deschide o pagină web, un fișier sau alt loc din document. Are două părți: textul afișat, între paranteze drepte, și adresa, între paranteze rotunde.
[textul afișat](adresa)

Cu text explicativ la trecerea cursorului[Google Fonts](https://fonts.google.com "Biblioteca de fonturi")Google Fonts + explicația

Reguli:

  • între ] și ( nu se lasă spațiu;
  • adresa unei pagini web se scrie completă, cu https://;
  • textul afișat descrie destinația: „Google Fonts”, nu „clic aici”;
  • legătura către un titlu: semnul #, apoi titlul scris cu litere mici, cu liniuțe în locul spațiilor și fără semne de punctuație (titlul „Reguli de bază” → #reguli-de-bază);
  • fiecare legătură se verifică printr-un clic în previzualizare.

9. Imagini

O imagine se scrie ca o legătură, cu semnul exclamării în față. Fișierul Markdown nu conține imaginea, ci numai trimiterea către fișierul-imagine.

![textul alternativ](calea către imagine)
Se scrie
![Schița afișului: titlu sus,
fotografie la mijloc,
contact jos](imagini/schita.png)
Se vede
Text alternativ – descrierea imaginii, scrisă între parantezele drepte. Este citit de cititoarele de ecran (programe folosite de persoanele cu deficiențe de vedere) și este afișat atunci când imaginea nu se poate încărca.
Cale relativă – drumul către fișier, pornind de la folderul în care se află documentul: imagini/schita.png.

Reguli:

  • imaginile se păstrează într-un folder imagini, aflat lângă fișierul .md;
  • calea se scrie cu bară oblică / și este relativă, nu de forma C:\Users\…;
  • numele fișierelor: litere mici, fără spații, fără diacritice (schita-afis.png);
  • textul alternativ descrie ce se vede în imagine, nu „imagine” sau „poză”;
  • formate: PNG pentru capturi de ecran și grafică, JPG pentru fotografii, SVG pentru desene vectoriale;
  • la predarea lucrării se predă tot folderul, nu numai fișierul .md.

Mărimea imaginii nu se poate stabili în Markdown de bază; imaginea apare la mărimea ei. Se redimensionează fișierul sau se folosește un element HTML: <img src="imagini/schita.png" alt="Schița afișului" width="300">.

10. Citate

Un citat este un text preluat dintr-o sursă sau un text scos în evidență, afișat retras, cu o bară verticală în stânga. Fiecare rând începe cu semnul > urmat de un spațiu.

Se scrie
> Un afiș bun se înțelege fără
> a fi citit până la capăt.
>
> — din regulile atelierului
Se vede

Un afiș bun se înțelege fără a fi citit până la capăt.

— din regulile atelierului

Un rând care conține numai > desparte paragrafele din interiorul citatului. În citat se pot folosi evidențieri și liste. Citatul se folosește și pentru observații: > **Atenție:** termenul de predare este vineri.

11. Cod și linie orizontală

Cod

Textul marcat drept cod este afișat exact așa cum a fost scris, cu font de lățime fixă; semnele din interior nu mai sunt interpretate ca Markdown.

Se scrie
Fișierul se numește `afis_v2.pdf`.

```
Titlu:  Ziua Porților Deschise
Data:   24 octombrie
Format: A3
```
Se vede

Fișierul se numește afis_v2.pdf.

Titlu:  Ziua Porților Deschise
Data:   24 octombrie
Format: A3
  • Cod în rând: între două accente grave `…` – pentru nume de fișiere, comenzi, taste.
  • Bloc de cod: între două rânduri formate din trei accente grave ``` – pentru mai multe rânduri; spațiile și rândurile se păstrează întocmai.

Linie orizontală

Un rând format din trei liniuțe ---, cu câte un rând gol înainte și după, produce o linie orizontală care desparte părțile documentului.

Fără rândul gol de deasupra, liniuțele transformă rândul precedent în titlu.

12. Caractere speciale

Semnele de marcare (*, #, _, `, [, ], >) au un rol în Markdown. Când un astfel de semn trebuie să apară ca atare în text, în fața lui se scrie o bară oblică inversă \, care îi anulează rolul.

Fonturile marcate cu \*stea\* au diacritice.Fonturile marcate cu *stea* au diacritice.Fonturile marcate cu stea au diacritice.
\# este semnul diez.# este semnul diez.un titlu: „este semnul diez.”

În interiorul codului (`…`) bara nu este necesară: acolo semnele apar întotdeauna ca atare.

Reguli de scriere îngrijită

  1. Un singur titlu de nivel 1; niveluri de titlu în ordine, fără salturi.
  2. Rând gol înainte și după titluri, liste, citate, blocuri de cod.
  3. Un singur fel de semne în tot documentul: - pentru buline, * pentru evidențieri.
  4. Diacritice corecte (ă, â, î, ș, ț) și ghilimele românești „…”.
  5. Numele fișierului: litere mici, fără spații și fără diacritice, cu extensia .md – de exemplu ghid-fonturi.md.
  6. Fișierul se salvează în codarea UTF-8 (codarea universală a caracterelor; în VS Code este afișată în bara de jos, în dreapta).
  7. Înainte de predare, documentul se citește în previzualizare, de la început până la sfârșit, și se încearcă fiecare legătură.
